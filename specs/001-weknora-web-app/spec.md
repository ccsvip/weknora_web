## Clarifications

### Session 2026-11-13

- Q: 操作者删除一段对话时，WeKnora 里对应的会话要不要一起删除？ → A: 本地对话和 WeKnora 会话一起删除。上游删除失败时，本地对话仍保留，并显示失败。活动记录只留一条不含正文的删除事件。
- Q: 在已有对话里继续提问时，发给 WeKnora 的是哪些内容？ → A: 只把这次的新问题发给已经绑定的 WeKnora 会话。
- Q: 操作者输入正确的访问口令后，这次通过要保持多久？ → A: 同一浏览器通过后保持有效，直到关闭该浏览器或主动退出。
- Q: 部署配置里没有填写访问口令时，产品应该怎么做？ → A: 拒绝启动完成，并明确说明缺少访问口令。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 向知识库提问 (Priority: P1)

操作者打开已经配置好的网页，选择一个自己有权使用的知识库，提出问题，
并在同一画面里看到回答逐步出现。回答来自既有的 WeKnora 知识对话。
上游返回引用时，引用和回答一起出现，操作者能区分哪些话有出处。

**Why this priority**: 没有提问和可核对的回答，这个产品就没有用途。
其余的历史、记录和部署都是为这条路径服务的。

**Independent Test**: 在已配置且至少有一个可用知识库的产品上，
选择知识库、提出一个非空问题，并核对回答、引用和失败时的画面。
不依赖对话列表或活动记录页面。

**Acceptance Scenarios**:

1. **Given** 操作者已通过访问口令，且存在至少一个允许使用的知识库，
   **When** 选择该知识库并提交一个非空问题，
   **Then** 问题立即出现在对话中，回答以进行中的状态逐步显示，
   结束后变为完成状态。
2. **Given** 上游在回答中返回了引用，
   **When** 回答结束，
   **Then** 每条引用都显示在该回答旁边，且能与正文区分。
3. **Given** 上游没有返回引用，
   **When** 回答结束，
   **Then** 画面保留上游返回的正文，并明确显示“没有引用”。
   产品不得自行补写引用或正文。
4. **Given** 回答仍在进行，
   **When** 操作者查看画面，
   **Then** 进行中、完成、失败三种状态可以靠画面本身区分，
   且进行中的回答不能被当成已完成的答案。
5. **Given** 上游拒绝访问、回答失败或传送中断，
   **When** 本次提问结束，
   **Then** 画面显示可区分的失败说明。已经收到的上游文字保留并标为中断。
   产品不得用自行编写的文字充当答案。
6. **Given** 宽屏浏览器，
   **When** 操作者进行提问，
   **Then** 当前对话、问题输入和回答处于同一套视觉体系中：
   统一的字号层级、间距、颜色和组件外观，而不是浏览器默认表单。

### User Story 2 - 管理已保存的对话 (Priority: P2)

操作者可以离开页面后再回来，找到以前的对话，继续提问，或删除不再需要的对话。
对话、消息和它们的状态保存在本产品中，不因关闭页面或重新启动而消失。

**Why this priority**: 利益相关者要求本产品自己管理对话并保存记录。
只靠上游的一次会话，无法完成“以后还能找到”这件事。

**Independent Test**: 连续创建两段对话，重新启动产品，
确认两段对话都还在、消息没有串。删除其中一段后，本产品和 WeKnora
里都找不到它，另一段不受影响。

**Acceptance Scenarios**:

1. **Given** 一段对话里已有完成的问答，
   **When** 操作者关闭页面并重新打开，
   **Then** 该对话仍在列表中，消息顺序和完成状态与离开前一致。
2. **Given** 产品被重新启动，
   **When** 操作者打开对话列表，
   **Then** 重启前已完成的对话和消息仍然存在，且仍只属于这次部署所创建的对话。
3. **Given** 列表中有多段对话，且目标对话已经绑定 WeKnora 会话，
   **When** 操作者打开其中一段并继续提问，
   **Then** 发给该 WeKnora 会话的只有这次的新问题，本地已有消息不会重发。
   新问答只写入这一段，其他对话的消息不变。
4. **Given** 一段对话已经在 WeKnora 中有对应会话，
   **When** 操作者确认删除且本地与 WeKnora 都删除成功，
   **Then** 该对话和其中的消息从本产品消失，WeKnora 中的对应会话也消失，
   其他对话不受影响，活动记录只增加一条不含正文的删除事件。
5. **Given** 操作者确认删除，但 WeKnora 会话删除失败或本地保存这次删除失败，
   **When** 删除结束，
   **Then** 该对话和消息仍可打开，画面显示失败，不显示为已删除，
   也不写入删除事件。不得只删掉本地而把 WeKnora 会话留下。
6. **Given** 一段对话所绑定的知识库在上游已经不存在或不再允许访问，
   **When** 操作者打开这段对话，
   **Then** 已保存的消息仍可阅读，新的提问被拒绝，并说明原因。

### User Story 3 - 查看活动记录 (Priority: P3)

操作者可以查看本产品保存的活动记录，了解对话何时创建、提问何时完成或失败、
对话何时被删除。记录用于回溯，不替代对话正文。

**Why this priority**: 利益相关者明确要求除对话本身之外还要保存记录。
它独立于提问路径，可以在对话已经可用之后增加。

**Independent Test**: 创建对话、完成一次提问、制造一次失败、删除对话，
然后只打开活动记录，核对四类事件是否按时间出现，且删除记录不含原消息正文。

**Acceptance Scenarios**:

1. **Given** 操作者创建对话并完成一次提问，
   **When** 打开活动记录，
   **Then** 能看到对应的创建事件和完成事件，事件包含时间和所属对话。
2. **Given** 一次提问因上游失败而结束，
   **When** 打开活动记录，
   **Then** 能看到失败事件和可理解的失败类别，记录中没有共享密钥。
3. **Given** 操作者删除了一段对话，
   **When** 查看活动记录，
   **Then** 能看到删除事件，且该事件不包含被删消息的正文。
4. **Given** 活动记录中有多个对话的事件，
   **When** 按某一段对话筛选，
   **Then** 只显示这段对话的事件。

### User Story 4 - 安全启动 (Priority: P2)

操作者按照文档中的一条启动命令把网页、服务端和记录存储一起运行起来。
监听端口、上游地址、访问口令和上游共享凭证都来自部署配置。
更换端口或凭证时，只改配置，不改产品源码。

**Why this priority**: 没有可重复的启动方式和可替换的配置，
对话功能无法交付给操作者使用，密钥也容易被写进源码或页面。

**Independent Test**: 使用示例配置填入测试用端口和凭证，
执行文档中的启动命令，打开网页并通过口令进入。
再把端口改到另一个值，只改配置并重新启动，确认新端口生效。

**Acceptance Scenarios**:

1. **Given** 一份填好的部署配置和可用的上游，
   **When** 操作者执行文档中的那一条启动命令，
   **Then** 网页、服务端和记录存储一起可用，操作者能打开提问页面。
2. **Given** 配置里的端口被改成另一个空闲端口，
   **When** 操作者只更新配置并重新启动，
   **Then** 网页从新端口打开，源码中的端口数字没有被修改。
3. **Given** 随产品提供的配置示例，
   **When** 检查该示例，
   **Then** 其中没有真实密钥，所有必须由操作者填写的项目都有说明。
4. **Given** 操作者未通过访问口令，
   **When** 直接打开对话页面，
   **Then** 不能看到知识库、对话和记录，也不能向上游发起提问。
5. **Given** 操作者已在当前浏览器通过访问口令，
   **When** 刷新页面、打开产品内其他页面，或产品被重新启动后回到同一浏览器，
   **Then** 不需要再次输入口令，仍可继续使用。
6. **Given** 操作者已通过访问口令，
   **When** 关闭该浏览器后再打开、改用另一个浏览器，或主动退出，
   **Then** 必须重新输入口令，才能看到知识库、对话和记录。
7. **Given** 部署配置中的访问口令未填写或只有空白，
   **When** 操作者执行启动命令，
   **Then** 启动不完成，说明中能看出缺少访问口令，提问页面不可使用。

### Edge Cases

- 没有可用知识库时，提问入口不可用，并说明是“没有可访问的知识库”，
  而不是显示一个会失败的空白对话。
- 配置缺少上游凭证，或凭证没有提问能力时，提问入口隐藏或禁用，并说明原因。
  产品不得改用另一份凭证或另一个租户重试。
- 上游返回无权访问或租户上下文错误时，本次操作失败并停止。
  产品不得更换租户后再试。
- 上游在回答开始后中断时，已收到的文字保留并标为中断，活动记录写下失败。
- 检索结果为空时，产品原样呈现上游的回答；没有引用就显示“没有引用”。
- 问题只有空白字符时，提交被拒绝，不创建新的上游提问。
- 问题超过 8,000 个字符时，提交被拒绝，并提示限制。
- 回答进行中时，不能再次提交，避免同一对话里出现两段重叠的回答。
- 在已绑定的 WeKnora 会话里继续提问时，只发送这次的新问题。
  产品不得重放本地历史，也不得补发未确认或已中断的消息。
  上游用来回答的上下文以该会话已有内容为准。
- 上游会话已经丢失时，已保存的消息仍可阅读；继续提问会被拒绝，
  并提示操作者新开一段对话。产品不得把新会话悄悄接在旧记录后面。
- 删除对话成功时，本产品和 WeKnora 中本产品创建的对应会话都必须消失。
  本地保存失败或 WeKnora 删除失败时，对话仍留在列表中并显示失败，
  不得显示成已删除，也不得只删掉本地而把 WeKnora 会话留下。
  只有两边都成功才写入不含正文的删除事件。
- 同一浏览器通过访问口令后，刷新、浏览产品内页面或重新启动产品都保持通过。
  关闭该浏览器、使用另一个浏览器或主动退出后，必须重新输入口令。
- 访问口令未填写或只有空白时，启动不完成，并明确说明缺少访问口令。
  此时不得进入可使用的网页。
- 活动记录和页面对操作者展示的文本中不得出现共享凭证、访问口令或上游密钥。
- 本功能不上传文档。任何画面都不得把未出现在本产品中的文件说成“已经可以搜索”。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 产品必须提供网页。操作者通过浏览器完成提问、查看对话和查看记录。
- **FR-002**: 打开对话、知识库和记录之前，操作者必须通过部署配置中的访问口令。
  同一浏览器通过后保持有效，直到该浏览器被关闭或操作者主动退出。
  刷新、浏览产品内页面和重新启动产品都不得单独要求再次输入口令。
  新的浏览器访问必须重新输入口令。操作者必须能够主动退出，退出后必须重新输入口令。
  本功能不提供注册、多用户目录或角色管理。
- **FR-003**: 产品必须列出当前凭证允许阅读的知识库，且不得列出其他知识库。
- **FR-004**: 操作者必须能够针对一个选定的知识库开始一段新对话。
- **FR-005**: 操作者必须能够在一段对话中提交非空问题，并看到回答逐步出现。
- **FR-006**: 上游返回引用时，产品必须在对应回答旁展示这些引用。
  上游没有引用时，必须明确显示没有引用。
- **FR-007**: 上游拒绝、回答失败或传送中断时，产品必须展示可区分的失败状态。
  已收到的上游文字必须保留并标为中断。产品不得用本地编写的文字充当答案。
- **FR-008**: 回答尚未结束时，产品不得把它显示为已完成的、可引用的最终答案。
- **FR-009**: 对话、消息、引用、完成或中断状态必须保存在本产品自己的存储中，
  关闭页面和重新启动后仍然可用。
- **FR-010**: 操作者必须能够列出、打开、继续和删除本部署创建的对话。
- **FR-011**: 删除对话成功时，本产品中的该对话、其消息，以及 WeKnora 中
  本产品创建的对应会话都必须消失。其他对话不得改变。
  本地保存失败或 WeKnora 会话删除失败时，本产品中的对话必须仍然存在并显示失败，
  不得显示为已删除，也不得只删除本地而把 WeKnora 会话留下。
- **FR-012**: 产品必须为对话创建、提问完成、提问失败和对话删除保存活动记录。
  记录包含时间、所属对话和事件类别。删除事件不得保留消息正文，
  并且只在本地对话与 WeKnora 会话都删除成功后写入。
  操作者必须能够按对话筛选记录。
- **FR-013**: 浏览器中的页面只能访问本产品。页面不得直接访问 WeKnora，
  也不得收到共享的上游凭证、平台凭证或模型供应商凭证。
- **FR-014**: 认证方式固定为：由本产品的服务端持有 WeKnora 工作区 API Key。
  本功能不使用终端用户的 WeKnora JWT，也不从浏览器接收上游密钥。
- **FR-015**: 本功能需要的上游能力是知识库阅读和 `chat`。
  不具备这些能力时，相关操作必须隐藏或禁用，并说明原因。
  产品不得为了完成操作去申请更宽的密钥。
- **FR-016**: 收到上游的无权访问或租户上下文错误时，产品不得更换租户后重试。
- **FR-017**: 知识回答必须来自 WeKnora 的知识对话。
  产品不得自行解析、分块、索引、检索或调用嵌入模型、向量库和大模型供应商来生成答案。
- **FR-018**: 对话标题在第一条非空问题提交时，取该问题去掉首尾空白后的前 40 个字符。
  此前标题等于知识库名称。列表中必须能靠标题和更新时间区分对话。
- **FR-019**: 空白问题必须被拒绝。超过 8,000 个字符的问题必须被拒绝并提示限制。
- **FR-020**: 一段回答进行中时，产品必须拒绝该对话上的另一次提交。
- **FR-021**: 知识库在上游消失或不再允许访问时，已保存消息仍可阅读，
  新提问必须被拒绝并说明原因。
- **FR-022**: 上游会话不存在时，已保存消息仍可阅读。
  产品不得在原对话下悄悄开始一段新的上游会话。
- **FR-023**: 提问、列表、失败和空状态必须使用同一套视觉体系。
  空知识库、等待回答、回答进行中、回答完成、回答失败、没有引用，
  必须能只靠画面区分。宽屏下当前对话和问题输入处于同一视图。
- **FR-024**: 操作者必须能用文档中的一条启动命令同时运行网页、服务端和记录存储。
- **FR-025**: 监听端口、上游地址、访问口令和上游共享凭证必须只来自部署配置。
  更换它们时不得要求修改源码。随产品提供的配置示例不得包含真实密钥。
- **FR-026**: 源码、配置示例、页面和活动记录中的展示文本不得写入真实密钥或固定端口。
- **FR-027**: 对话、消息和活动记录必须通过资源路径创建和读取。删除对话时同时删除其消息。
  不另设更新接口。对话标题在提交第一条问题时写入。助手消息的状态随同一次创建请求
  从进行中变为完成或中断。活动记录写入后不再修改。
  页面不得另用一套动作式远程接口访问这些资源。
- **FR-028**: 在已绑定 WeKnora 会话的对话中继续提问时，产品必须只把这次的新问题
  发给该会话，不得重发本地已有消息，也不得补发未确认或已中断的消息。
- **FR-029**: 访问口令未填写或只有空白时，产品必须拒绝启动完成，
  并明确说明缺少访问口令。此时网页不得进入可使用状态。

### Key Entities *(include if feature involves data)*

- **知识库引用**: 上游知识库在本产品中的可选择项。包含上游标识、显示名称和是否仍可访问。
  不包含文档正文、切片或向量。
- **对话**: 操作者的一段连续提问。属于本部署。绑定一个知识库引用和上游会话标识。
  包含标题、创建时间、更新时间和是否还能继续提问。
  删除成功后，本产品不再保留该对话，其上游会话标识也不再指向仍存在的 WeKnora 会话。
- **消息**: 对话中的一条问题或回答。包含角色、正文、状态（进行中、完成、中断）
  和时间。回答可以附带零到多条引用。
- **引用**: 回答所依据的上游出处。包含可显示的标题或片段标识，以及操作者能看懂的摘录。
  没有上游出处时，不创建引用。
- **活动记录**: 本产品写下的回溯事件。包含时间、事件类别、所属对话和简短说明。
  说明中没有密钥，删除事件中没有消息正文。
- **部署配置**: 启动产品所需的端口、上游地址、访问口令和上游共享凭证。
  不属于对话数据，也不出现在页面和活动记录中。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 从未用过本产品的操作者，在上游和配置已经可用的前提下，
  能在 3 分钟内完成“通过口令、选择知识库、提出问题、读完回答并看到引用或没有引用的提示”，
  且中途不需要阅读源码。
- **SC-002**: 回答进行期间，画面至少每秒更新一次已收到的内容，
  直到回答完成或失败。操作者不用刷新页面。
- **SC-003**: 重新启动后，重启前已完成的对话和消息 100% 仍可按原顺序打开。
  抽查两段各 50 条消息的对话时，消息不得串段。
- **SC-004**: 在无权访问、传送中断和检索为空这三种检查中，
  100% 的失败或空引用都呈现为可区分状态，且不出现由本产品编造的答案或引用。
- **SC-005**: 在包含 100 段对话的列表中，操作者能在 10 秒内按标题找到目标对话并打开，
  消息顺序与保存时一致。
- **SC-006**: 只修改部署配置并重新启动后，新的监听端口生效。
  检查源码、配置示例、页面和活动记录时，发现 0 处真实密钥和 0 处写死的监听端口。
- **SC-007**: 评审者只看画面，就能判断当前是空知识库、等待、进行中、完成、失败或没有引用。
  抽查上述每种状态各一次，6 次全部判断正确。
- **SC-008**: 创建、完成、失败和删除各发生一次后，活动记录在 5 秒内能按对话筛选出对应事件。
  删除事件不含被删消息正文。

## Assumptions

- 本规格承接 WeKnora Web Constitution 1.0.0。产品是 WeKnora 的网页客户端，
  不是 WeKnora 本身的改版。
- 使用对象是单一操作者部署。一台部署使用一份服务端持有的工作区 API Key。
  不在本功能中做账号注册、邀请或按人隔离。对话隔离的边界是“本部署创建的对话”。
- 访问口令是部署配置中的一项共享口令，用来避免网页裸露在网络上。
  它不是 WeKnora 的用户体系。通过后只在同一浏览器保持，直到关闭该浏览器或主动退出。
  口令未填写或只有空白时，启动不完成。
- 本功能只做知识对话。智能体对话、智能体管理、知识库编辑、文档上传、
  Wiki、即时通讯机器人和 WeKnora 服务端修改都不在范围内。
- 因此，宪章里“文档尚未解析完成不得声称可搜索”的检查在本功能中没有上传路径。
  对应的可观察行为是：产品不得显示任何文件的“已可搜索”状态。
- 上游发布线在宪章批准时为 v0.9.0。本规格不锁定补丁版本。
  实现计划必须写明实际对接的 WeKnora 版本。
- 问题长度上限取 8,000 个字符。标题取第一条问题的前 40 个字符。
  这两个数字是本规格的默认值。
- 活动记录只保留到操作者可用的产品存储中，不另设自动过期。
  删除对话后，删除事件继续保留。
- 视觉品质是验收条件，不是装饰性建议。计划必须选择一个主流网页界面框架，
  并在计划中写明具体框架。不得交付未加设计的浏览器默认页面。
- 服务端语言只能在 Python 和 Go 之间选择。计划必须选定一个并写明，
  不得改用第三种语言。
- 记录存储必须是本产品自己的数据库。计划选定具体数据库并写明。
  数据库保存对话、消息、引用和活动记录，不保存知识库正文的副本。
- 启动方式必须是 Docker。文档中的那一条启动命令必须能同时拉起网页、
  服务端和数据库。
- 部署配置必须由受维护的 `.env` 提供。仓库包含不含真实密钥的示例文件。
  端口、上游地址、访问口令和上游 API Key 都从这里读取。
- 非显而易见的逻辑必须有简短注释，说明为什么这样做。
  注释不重复代码表面的动作。
- 页面只调用本产品的资源式接口。对 WeKnora 的访问集中在服务端的一个客户端里，
  由实现计划按宪章落到具体模块和契约测试。

## Constitution Compliance

本规格对应 Constitution 1.0.0。

- **原则 I**：回答只来自 WeKnora 知识对话。本产品不实现解析、索引、检索，
  也不直接调用模型或向量库。见 FR-017。
- **原则 II**：页面只访问本产品。上游的成功信封、失败信封和知识对话流
  由服务端的一个客户端承接。见 FR-013。契约测试在实现计划中落地。
- **原则 III**：认证方式是服务端持有的工作区 API Key，只放在部署配置中，
  不进入浏览器。本功能不使用终端用户的上游登录凭证。见 FR-014、FR-025、FR-026。
- **原则 IV**：本功能声明的能力是知识库阅读和 `chat`。
  不需要 `ingest`、`read_agents`、`manage_agents`。
  只有在上游把“列出知识库”归到 `manage_kbs` 时，计划才可以增加这一项，
  并且仍然只能展示该密钥允许的知识库。无权操作必须隐藏或禁用。见 FR-003、FR-015。
  本部署不得读取或继续其他调用方的上游会话。见 FR-022。
- **原则 V**：引用随回答展示；没有引用要明示；失败和中断不得伪装成完成答案。
  见 FR-006、FR-007、FR-008。本功能没有文档上传，因此没有“已可搜索”状态。
- **交付约束**：计划必须写明 WeKnora 版本，并落实 Assumptions 中的
  语言、数据库、界面框架、启动方式和部署配置。这些选择必须满足 FR-024 到 FR-027。
