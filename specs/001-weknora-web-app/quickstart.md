# Quickstart: WeKnora 网页对话台

用本文验收规格，不代替实现。接口字段见 [contracts/openapi.yaml](contracts/openapi.yaml)，上游字段见 [contracts/weknora-v0.9.0.md](contracts/weknora-v0.9.0.md)，界面路由与渲染见 [contracts/web-ui.md](contracts/web-ui.md)，表见 [data-model.md](data-model.md)。

## 前提

- 已安装 Docker，并且可以使用 `docker compose`。
- 有一套 WeKnora v0.9.0，其工作区 API Key 具备 `retrieve` 和 `chat`。
- 该密钥至少能阅读一个知识库。另备一个没有知识库的密钥，供空列表验收。

## 配置

在仓库根目录复制示例配置为 `.env`。填入下面的名称，值不要写进源码：

- `WEB_PORT`：浏览器访问端口
- `API_PORT`：服务端在容器内的监听端口
- `POSTGRES_PORT`：数据库在容器内的监听端口
- `POSTGRES_USER`、`POSTGRES_PASSWORD`、`POSTGRES_DB`
- `WEKNORA_BASE_URL`：到 WeKnora 的基址，不含尾部路径
- `WEKNORA_API_KEY`
- `ACCESS_PASSWORD`：访问口令
- `ACCESS_SESSION_SECRET`：签名密钥，与口令不同
- `ACCESS_COOKIE_SECURE`：本地 HTTP 用 `false`，HTTPS 用 `true`

示例文件里这些值必须为空或为不含真实密钥的说明。源码和 compose 文件不得出现具体端口数字。

一条启动命令：

```shell
docker compose up --build
```

浏览器只打开 `http://localhost:<WEB_PORT>`。不要另开服务端端口。
登录页路径为 `/login`，对话台为 `/`，活动记录为 `/activity`。刷新后两个已登录路径仍应打开，不得 404。

## 验收场景

### 1. 没有访问口令时不能启动

把 `ACCESS_PASSWORD` 留空后执行启动命令。服务端进程以非零状态退出，日志说明缺少 `ACCESS_PASSWORD`，且不打印口令。浏览器打不开可用的提问页。对 `WEKNORA_API_KEY` 和 `ACCESS_SESSION_SECRET` 各做一次同样的检查。

### 2. 口令、刷新和重启

填好配置并启动。错误口令不能进入对话。正确口令后能看到知识库。刷新页面和在产品内打开记录页都不再要口令。执行：

```shell
docker compose restart api
```

回到同一个未关闭的浏览器，仍保持通过。主动退出后，必须重新输入口令。关闭浏览器再打开，也必须重新输入口令。

### 3. 提问、引用和失败

选择一个知识库并提交一个非空问题。问题立刻出现，回答以进行中状态逐步出现，完成后变为完成。回答进行期间，画面上的回答文字至少每秒变化一次，直到完成或失败。有引用时，引用在回答旁边且不混进正文。没有引用时，正文仍是上游返回的内容，并显示“没有引用”。若上游正文含表格、列表或代码块，完成态下应渲染为对应结构，而不是一整段未处理的标记符号。

把 `WEKNORA_BASE_URL` 改成不可达地址并重启后提问。画面是失败，已收到的文字如果存在则标为中断，不出现由本产品编写的答案。恢复正确地址后，403 或租户冲突也只表现为一次失败，不自动改去别的租户。

空白问题和超过 8,000 字的问题被拒绝，不产生新的上游提问。回答未结束时不能再次提交。

### 4. 继续提问只发送新问题

在同一段对话再提一个与上文有关的问题。回答仍落在这一段。自动化契约测试必须证明发给 WeKnora 的 `query` 只有这句新问题，并只带这一段的知识库 id。手工验收只确认新问答没有写进其他对话。

### 5. 历史、重启和不能继续的对话

创建两段对话后执行：

```shell
docker compose restart
```

两段对话和消息都还在，顺序不变。自动化测试另外种入 100 段对话，列表一次返回这 100 段，并且该请求在 10 秒内结束。手工抽查时，从这份列表按标题打开其中一段，用时也不超过 10 秒。删除其中一段且上游删除成功时，本产品和 WeKnora 里都找不到它，另一段仍在。活动记录有一条不含正文的删除事件。

让上游删除失败时，该对话仍可打开，画面显示失败，没有删除事件。

知识库被取消访问或上游会话已经不在时，旧消息仍可阅读，新提问被拒绝。

### 6. 活动记录

完成一次提问、制造一次失败、删除一段对话。按该对话筛选，5 秒内能看到创建、完成或失败、删除中实际发生的事件。记录页和页面源代码里搜不到 API Key、访问口令和签名密钥。

### 7. 视觉状态

在至少 1100px 宽的窗口查看。对话列表、对话和输入区同时可见，引用在旁侧。对照下面六种画面，评审者应能只看画面说中状态：没有知识库、等待、进行中、完成、失败、没有引用。页面使用纸色编辑台（纸色底、墨色字、强调绿），不是浏览器默认表单，也不是通用紫渐变后台。

### 8. 端口只来自配置

把 `WEB_PORT` 改成另一个空闲端口，不改源码，重新执行启动命令。网页从新端口打开。在源码、compose 文件、示例配置、页面和活动记录中搜索，不应找到真实密钥，也不应找到写死的产品监听端口。

### 9. 自动化命令

实现完成后，在不依赖真实 WeKnora 的情况下运行服务端契约测试和页面状态测试。二者都应通过。契约测试用假上游覆盖 [WeKnora 契约](contracts/weknora-v0.9.0.md) 里列出的信封、SSE、空引用和 403/409 只请求一次。页面测试覆盖六种状态、Markdown 表格/列表/代码块、进行中不得显示为完成，以及未登录打开 `/` 或 `/activity` 时进入 `/login`。

## 停止

```shell
docker compose down
```

这条命令不要求删除数据库卷。需要清空本地记录时，再显式删除该卷。
